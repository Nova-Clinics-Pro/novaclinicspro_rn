## Original unsafe control flow

`ChoiceScreen` read `applicationId` from `useLocalSearchParams()` and selected
it before the authenticated registration-status continuation. A navigation URL
could therefore choose the ID given to the application-detail query and the
onboarding store.

## Production correction

`ChoiceScreen` no longer reads navigation parameters. It derives its effective
application ID only when an authenticated applicant is present and
`registrationStatus.data.continuation.kind` is `approved_choice`. The status
query is enabled for an authenticated applicant without a route-ID exception.

## Authority trace

1. Authentication supplies the applicant identity.
2. `/registration-status/me` supplies the server-selected continuation.
3. Choice uses only that continuation to select the application.
4. `GET /applications/{application_id}` independently maps the authenticated
   user to an organization user and rejects applications whose `created_by` is
   different. This is defense in depth; it did not make the frontend override
   acceptable.
5. `/auth/me` remains the authority for tenant membership in the root gate.

## Before/after behavior

| Scenario | Before | After |
| --- | --- | --- |
| Valid approved continuation | Loads its application | Unchanged |
| Conflicting route ID | Route ID overrides continuation | Ignored |
| Route ID without continuation | Could enable application detail | Disabled; empty/safe state |
| Pending/rejected plus route ID | Could enable application detail | Disabled; empty/safe state |
| Status loading/error plus route ID | Could enable application detail | Disabled; loading/safe state |
| Cached continuation without an authenticated applicant | Could be reused if cache state leaked | Disabled |

## Focused security coverage

The Choice component tests prove that the continuation application ID drives
the detail query and onboarding store, while conflicting or standalone route
IDs cannot do so. These are deterministic mocks; they do not replace backend
authorization testing.
