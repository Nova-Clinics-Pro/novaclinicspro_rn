## 5. Query-suppression results

The real datasource received **zero calls** for all invalid/untrusted cases:

- missing, null, or empty continuation;
- wrong kind;
- missing, empty, or invalid UUID application ID;
- missing, blank, or whitespace-only tenant name;
- nonapproved status;
- unresolved registration status;
- unauthenticated applicant;
- route-supplied ID without a trusted continuation.

For these states, a disabled query observer can exist, but the real query function did not execute and the mocked datasource was not called. No application context rendered.

## 6. Positive and identity-transition results

The valid approved case produced exactly one datasource request using the canonical validated application UUID and rendered the returned clinic context.

With the same QueryClient:

1. A delayed Applicant A request could not populate Applicant B after B received a distinct valid continuation; B's request used only B's ID.
2. A delayed A response did not populate ChoiceScreen after logout and did not cause an additional request.
3. A delayed A response did not populate Applicant B when B's continuation was malformed; no B request was issued.

These tests establish query-execution and datasource-call suppression with mocked I/O. They do not establish live HTTP transport or backend authorization behavior.
