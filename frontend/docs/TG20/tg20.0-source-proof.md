## 5. Template-resolution proof

Source proves the exact AUTH-1 sequence:

1. `OnboardingService.get_onboarding_status()` calls
   `TemplateRepository.get_tenant(tenant_id)` and returns not-found if absent.
2. It calls `get_template_by_clinic_type(tenant_dict["clinic_type"])`.
3. If absent, it calls `get_template_by_clinic_type("general")`.
4. If still absent, it returns not-found; TG20 maps this to terminal
   `ONBOARDING_TEMPLATE_UNAVAILABLE` without exposing raw text.
5. If the resolved template lacks `code`, current source fails; TG20 maps this to
   terminal `ONBOARDING_TEMPLATE_INVALID`.
6. It calls `get_setup_steps(template_code)` read-only.

`SQLAlchemyTemplateRepository.get_template_by_clinic_type()` filters
`OrgTemplate.clinicType/clinictype` and `is_active`, limits to one, and performs
no mutation. `get_setup_steps()` reads the template/base template and merges
steps in memory. No assignment table, assignment service, materialization
service, template creation, or setup-progress mutation participates.

TG20's evidence adapter may reuse the port/adapter operations directly after
Platform Foundation authorization, avoiding the legacy `is_org_admin` check in
the public onboarding status method. This is an adapter composition, not a new
template owner. Retry repeats these reads only. AUTH-1 is fully source-backed.
